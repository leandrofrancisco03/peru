Una propuesta lleva diez días en el CRM y el sistema prepara otro mensaje. Sin embargo, el cliente respondió ayer a otro asesor. El problema no es la falta de recordatorios: es que el seguimiento no consulta el contexto antes de actuar.

Esta guía propone un circuito para equipos comerciales de servicios y suministros en Perú. Se centra en lo que ocurre después de enviar una propuesta, sin sustituir la evaluación comercial ni prometer una mejora de ventas.

## Empieza por una próxima acción concreta

«Hacer seguimiento» no explica qué necesita el negocio. Registra responsable, fecha de revisión, motivo y siguiente actuación. Puede ser verificar una especificación, esperar una aprobación o cerrar una oportunidad descartada. Cada situación requiere un comportamiento distinto.

Conserva el identificador y la versión de la propuesta. Si el cliente recibe una actualización, las tareas de seguimiento de la versión anterior deben detenerse o revisarse. La [guía de cotizaciones B2B](/blog/automatizar-cotizaciones-seguimiento-peru) explica cómo organizar esa aprobación previa.

## Distingue una tarea interna de un mensaje al cliente

Una tarea interna pide al asesor que revise el caso. Un mensaje externo utiliza un canal y puede requerir condiciones adicionales. No conviertas cada vencimiento de tarea en un envío automático.

| Situación | Próxima acción razonable |
| --- | --- |
| Falta una especificación | Pedir al responsable que confirme el requisito |
| El cliente respondió | Revisar respuesta y cancelar el aviso anterior |
| Hay una nueva versión | Validar cuál sigue vigente |
| El cliente pidió una pausa | Registrar la pausa y su condición de revisión |
| La oportunidad fue descartada | Detener la secuencia de esa oportunidad |

La regla debe consultar el estado actual justo antes de ejecutar. La fecha calculada al inicio sirve como intención, no como autorización permanente de contacto.

## Define condiciones de parada

Un flujo debe detenerse si existe una respuesta pendiente de revisión, una baja del canal, una propuesta retirada o un cambio de responsable sin aceptar. Si los sistemas discrepan, genera una tarea interna para resolver el conflicto.

Para [automatización de WhatsApp](/servicios/whatsapp-api-oficial), confirma las condiciones efectivamente habilitadas para tu cuenta y el tipo de comunicación. La guía describe el proceso de decisión; no presupone permisos, plantillas o disponibilidad de una función de plataforma.

## Prioriza con datos que puedas explicar

No necesitas una puntuación opaca para empezar. Separa propuestas sin próxima acción, propuestas con datos pendientes y propuestas que esperan una decisión del cliente. Revisa la antigüedad junto con el contexto: un proyecto pausado por acuerdo no equivale a un asesor que olvidó responder.

Si utilizas IA para resumir conversaciones, conserva acceso a los mensajes originales autorizados y exige revisión cuando falte contexto. El resumen no debe inventar una aceptación, una objeción o una fecha comprometida.

## Ejemplo de una revisión diaria

Un equipo B2B revisa cada mañana las tareas que vencen. El flujo obtiene la versión vigente, comprueba si hubo respuesta y prepara una lista de excepciones. El asesor elige la actuación; solo las comunicaciones que cumplan las condiciones acordadas continúan por el canal correspondiente.

El escenario de [cotizaciones técnicas en Arequipa](/peru/arequipa) ayuda a identificar qué cambios requieren nueva revisión. Para asesorías y estudios, consulta el recorrido de [servicios profesionales](/sectores/servicios-profesionales).

## Comprueba los fallos antes del primer envío

Prueba una respuesta recibida mientras se ejecuta la tarea, dos asesores actuando sobre la misma propuesta, una pausa registrada después de programar y un fallo al guardar el resultado. Un reintento no debe producir dos mensajes ni dar una tarea por completada sin evidencia.

Mide oportunidades sin responsable, seguimientos cancelados correctamente y tiempo hasta revisar una respuesta. Completa la [ficha de diagnóstico](/recursos) con una propuesta ficticia y una excepción. Ese registro permite evaluar el piloto sin empezar por una secuencia masiva de mensajes.
